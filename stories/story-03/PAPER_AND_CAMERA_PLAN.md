## 2. 紙本版面

- 每頁大標題標明是哪一道門；算式依序向下排列，右側為固定位置的答案欄，每題一格，約 28–30 mm。七題頁需實際打樣檢查間距與 A4 留白。
- 圖像輔助與各題算式一致：合併兩群、標示拿走的物件、留下空盤表示 0。裝飾不混入計數區；若印刷空間不足，完整帶算圖留在平板的各題提示中，不擠小答案格。
- 黑白列印也清楚。答案格內不印題號、灰色範例、底紋或正解；格線、算式與題號都要避開裁切區。
- 頁角可用不含答案的關卡／版面標記，協助確認頁面與方向；標記只能識別題卷與格子，不能代替讀取手寫答案。
- 中文沿用專案注音文字圖，不將字型本體嵌入公開 PDF。列印版已使用 28 mm 空白格、固定題序、四角定位方塊及不含答案的題卷識別 QR；見 [PDF 與版面資料](worksheets/README.md)。
- 不需額外把 6／7 個答案抄成密碼。系統按答案欄的題序組合，少掉抄錯或記不住的負擔。
- 沒有印表機可手畫對應格子，由大人抄同一組題目；此時可用單格掃描或數字鍵，不承諾任意手畫版面可自動整頁定位。
- 尚不熟悉寫字可先口答／實物算，再由大人協助記錄。每道門之間有故事或休息，進度可保存。

## 3. 孩子的操作與掃描方式

1. 平板講到一道門，孩子拿出對應紙本，完成該頁 6 或 7 題。
2. 按「掃描這張紙」才請求相機權限；預設後鏡頭，紙放穩後按「拍一下」。
3. **目標是每關拍一次答案欄**：定位紙本後，把 6／7 格分別裁切，逐格辨識手寫數字，再按固定題序組合。不是自由辨識整頁文字、算式或 20 題混在一起。
4. 顯示同順序的格子預覽與候選數字。空白／低把握的格子保留待確認位置，不能跳過而使後面數字前移。
5. 孩子可修正單格、單格重拍或重新拍這一頁；最後按「這些是我寫的」才判數學答案，不需機械式連按 20 次確認。
6. 全組答案核對正確才開門；若某題不對，只提示該題，保留其他已完成格。算完更正即可，不重做整張紙。
7. 每門成功畫面等待「繼續」。第三門開後直接開寶箱，不再追加第 21 題或第四組密碼。

一次讀 6／7 格是待驗證的工程目標，不保證一次拍攝就全數成功。若整欄定位或某格不清楚，保留單格掃描與數字鍵；是否適合正式使用要看兒童字跡與目標平板結果。

「拍一下」僅在記憶體取樣，不自動下載照片、寫相簿或上傳。後鏡頭預覽、方向與裁切必須一致，不套用 Story 02 前鏡頭的鏡像站位畫面。

## 4. 辨識錯誤與數學錯誤分開

| 狀況 | 顯示／行為 |
| --- | --- |
| 頁面不是目前關卡、題卷版本錯誤、格數或定位不符 | 先確認拿對紙；不按錯頁位置產生密碼。 |
| 空白、太暗、模糊、未對準或無有效候選 | 「這一格我還看不清楚。」提供單格重拍或數字鍵；空白不當 0。 |
| 低把握、多個字或非數字 | 不猜成預期答案、不判算錯；讓孩子更正。 |
| 模型讀成另一個數字 | 孩子可修正，確認後再判題；不要求一直重寫模型認不出的清楚字跡。 |
| 讀值已確認，數學答案錯誤 | 小松鼠按該題示範合併／拿走；其他正確答案保留。 |
| 權限拒絕、相機中斷、不支援或模型失敗 | 使用同樣的六格／七格數字鍵完成該關；不減少題數、不直接給正解。 |

辨識器不能利用預期答案調整候選。例如這題應是 6，不能把模糊的 8 自動改成 6。密碼以固定長度的字串／陣列核對，保留 0 與格子順序；不以數值轉換忽略空格或前導零。重複確認不重複開門或發獎。

## 5. 技術可行性與限制

瀏覽器本機手寫數字分類有可用方法，例如 [TensorFlow.js 官方手寫數字示範](https://www.tensorflow.org/js/tutorials/training/handwritten_digit_cnn)。但基準資料集分數不代表平板拍攝兒童紙本的效果；[TensorFlow 官方案例](https://blog.tensorflow.org/2022/08/jax-on-web-with-tensorflowjs.html) 亦展示字跡不同造成誤判。本專案還沒有這項實測，不能承諾準確率。

[Tesseract 官方 FAQ](https://github.com/tesseract-ocr/tessdoc/blob/main/FAQ.md) 說明其主要針對印刷文字，手寫效果有限，因此不直接以一般整頁 OCR 作第一版。先評估單數字模型，再把固定欄位各自辨識後組合；套件、模型權重授權與效能仍須另核對，尚未選定公開依賴。

鏡頭需要安全來源與使用者權限，見 [getUserMedia 文件](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。Pages 已是 HTTPS，仍需驗證 iPad／Android 的後鏡頭與方向。

可沿用 [既有鏡頭方法](../../engine/SENSORS_REUSE.md) 的權限、取消與離場清理原則；姿勢模型和三區判斷不能辨識數字，不直接改成答案判定。先做獨立實驗，驗證後才抽取共用方法。

## 6. 建議的工程順序

1. 已完成：依使用者確認輸出三頁孩子版 PDF、獨立家長解答，核對注音、20 題、A4 尺寸、空白格及未嵌入字型。實際印表機輸出仍需按列印說明確認。
2. 在 `experiments/number-scan/` 獨立驗證單格取樣、裁切、預覽、更正及候選模型，不讀寫故事存檔。
3. 加入固定答案欄定位與透視／旋轉處理，辨識 6／7 格；辨識前核對頁面、格線、順序及採樣品質。逐格失敗不可拖垮整組。
4. 用不同字跡與目標平板記錄單格正確率、整組一次成功率、錯讀／拒識、更正次數和等待時間；不能只報單格高分就宣稱長密碼可靠。
5. 在 Story 03 先接數字鍵完成全部 20 題與三道門，再接拍攝結果。兩種輸入使用同一題庫、順序及答題檢查。
6. 驗證兩個結局、題卷一致性、刷新與跨故事存檔；平板確認後才依既有流程發布。

已建立 `worksheets/math10-v1.pdf`（三頁）、`worksheets/math10-v1-answers.pdf`、題目 JSON 與定位 JSON。獨立實驗頁及驗證後的 `engine/number-scanner.js`／worker 尚未建立。未來狀態為 `adventure.story-03.state`，含題卷版本、20 題的已確認進度與三道門狀態；不保存影像或未確認候選。

## 7. 第一輪驗收條件

- 20 題恰為 6／7／7，三組密碼與題序一致；每題都有作用，不只用最後一道答案。
- 正解／錯解都能辨識與更正；不以正解偏置模型，模型失敗也不縮成三題。
- 空白與 0 不混淆；答案欄少一格不移位，反向／歪斜拍攝、錯頁與錯版均能攔下或明確要求更正。
- 模糊、塗改、淡鉛筆、影子、格線、雙位數及數字不同寫法均有合理拒識／修正方法。
- 大人字跡與孩子實際字跡分開記錄；字型合成圖或 MNIST 分數不代替紙本平板實驗。
- 權限拒絕／忽略、模型下載或推論失敗、背景、旋轉、取消後遲到的授權，都能回到數字鍵。
- 完成、取消、離場或背景時釋放相機與 worker；影像不進 localStorage、log 或網路請求。
- 只錯一題時其餘已確認結果保留；刷新後仍可續做該關，不重新開相機、不沿用錯版題卷進度。
- 全手動、聲音關閉、未拿木片或拿到未使用皆可走普通結局；使用木片可走祕密結局。

以上互動驗收仍待工程階段；本階段已完成文件與列印版，PDF 驗證結果見 [列印說明](worksheets/README.md)。
